Why cronchords

Free
The sync runs on GitHub Actions, its state lives in a free Supabase project, and the dashboard is a static site. There is nothing to pay for.
Your own keys
You create the Spotify app and the Google OAuth client yourself. No third party ever sees your tokens.
Runs on its own
It syncs every hour, and no computer of yours has to be on. If you'd rather, run it on a Raspberry Pi, in Docker or as a systemd service.
Open source
MIT licensed. Fork it, and your copy is yours to run and change.

How it works

You pair a Spotify playlist with a YouTube playlist and pick a direction. Every hour, the worker carries the changes over to the other side.

  • Spotify → to YouTube New songs are copied to YouTube. Nothing is removed.
  • Spotify ← from YouTube New videos are copied to Spotify. Nothing is removed.
  • Spotify ↔ and YouTube Additions and removals go both ways. Replace a wrong match in the playlist, and the right one is remembered.
Careful matching
Title, artist and length have to agree. Covers, live versions and remixes only match each other, and album uploads from Topic channels come first.
Searched once
Every match is cached by ISRC, so a song is looked up only once, however many playlists it's on.

The shared list

YouTube allows about 100 searches a day, and most people search for the same songs. So the matches every user found go into youtube-spotify-mapper, an open list of Spotify tracks and their YouTube videos, and every worker looks there before it searches.

Hard to troll

  • Every pair is checked by a machine, with the same rules as a search result.
  • A correction made by hand needs at least two accounts that agree.
  • Accounts younger than 90 days don't get a vote.
  • Every worker checks again whatever it takes from the list.

Privacy

What is shared
Track and video IDs only. The names of your playlists, and which songs are on which, never leave your database.
What is public
The shared pairs sit on a branch of your fork, so anyone can see which songs you sync.
Turning it off
One variable: SHARE_MATCHES=false.
Taking it back
Delete the cronchords-export branch. The list drops your matches with its next update.

Limits

Worth knowing before you fork.

Spotify
The app's owner needs Spotify Premium, and only playlists you own or collaborate on can be synced.
YouTube
About 100 new songs a day: adding one costs 50 of the 10,000 daily units. A big playlist takes a few days the first time.
Reconnecting
Spotify has to be reconnected every six months. The dashboard shows when.

Setup

About 20 minutes. The setup guide in the README walks through every step.

  1. Fork the repository
  2. Create a Supabase project and run the SQL migrations
  3. Deploy the dashboard on Vercel, Netlify or GitHub Pages
  4. Create a Spotify app and a Google OAuth client
  5. Connect your accounts and pair the playlists
